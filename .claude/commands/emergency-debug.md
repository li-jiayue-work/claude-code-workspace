# Command: Emergency Debug

## 触发

生产环境出现紧急问题，需要快速响应。

## 分级

| 级别 | 定义 | 响应时间 | 流程 |
|------|------|----------|------|
| P0 | 系统不可用 | 立即 | 完整 debug + hotfix |
| P1 | 核心功能受损 | 30min | 完整 debug + 修复 |
| P2 | 非核心功能受损 | 2h | 标准 debug 流程 |

## 执行流程（P0/P1）

1. **止血**
   - 确认影响范围
   - 记录当前状态（日志、监控截图）
   - 评估是否需要回滚最近的发布

2. **定位**
   - 使用 debugger agent
   - 重点检查最近的部署变更
   - 对比错误出现时间与部署/配置变更时间

3. **修复**
   - 最小修复
   - 先止血再根治
   - Hotfix 分支：`hotfix/<description>`

4. **验证**
   - 确认修复生效
   - 监控关键指标恢复

5. **复盘**（事后）
   - 完整的 debug report
   - 更新 memory/mistakes.md
   - 评估是否需要流程/监控改进

## 禁止事项

- 紧急情况下不跳过 code review（可简化为 reviewer agent 快速扫）
- 不直接在生产环境修改代码
- 不止血就开始深度分析——先让系统恢复
- 不跳过事后复盘
