# 内容提取方法

## 核心原则

**按材料顺序做笔记，再把笔记排成页面**。不要"先写中心论点，再回头找材料填空"。

每页应是以下五种类型之一，且直接来源于材料：
- 材料中真正提出的问题
- 材料给出的判断或关键词
- 材料用到的故事/数字/例子
- 材料自然叙述的下一步
- 停在未解问题或余味的结尾

## 读后笔记

记录以下内容：
- 基础元数据（标题、作者、日期、链接）
- 材料推进顺序（走了哪几步）
- 原始问题（访谈/文章中真正被提出的问题）
- 原始判断（嘉宾/作者的核心主张）
- 例子（具体的故事或数字）
- 反复出现的线索词
- 张力点（冲突、反转、反常识）
- 有分量的原句

内部总结允许在此步骤出现，但不能直接成为页面标题。

## 候选页清点

按材料顺序列出候选页，每页标注：
1. 来源位置
2. 页面焦点（读者应记住的一句话）
3. 支撑锚点（判断/原话/例子/数字/概念，至少一项）
4. 推荐版式
5. 自检

任何节点凑不出锚点 → 直接删除。

## 访谈材料处理

- 保留推动回答的问题
- 保留判断和概念词
- 保留提问者的追问/打断
- 保留例子
- 压缩寒暄、重复确认、口头禅、长问题铺垫

检验标准：这句话是否改变了回答的方向？是→保留，否→删。

## 长文材料处理

- 保留文章推进感
- 优先看作者在哪一段开头说了什么
- 优先看哪些段落提供了背景
- 优先看哪个小标题下面方向变了
- 优先看文章停在哪
- 不做"把文章小标题变目录"

## 页面内容类型

| 类型 | 说明 |
|------|------|
| 原问题 | 真正推动对话的问题 |
| 原话 | 有分量的直接引用 |
| 例子 | 具体的故事或案例 |
| 对比 | 前后变化或对立立场 |
| 结构页 | 提示读者即将进入的新章节 |
| 线索追踪 | 同一关键词在不同位置的含义变化 |
| 余味 | 材料留下但未回答的问题 |
| 核心总结 | 高密度笔记，每条有锚点和获得感 |

## 核心总结页

- 高密度笔记供读者带走，不是生成者的评论
- 每条必须反映材料中已表达的观点
- 每条应有获得感：判断/机制/数字/例子/方法中至少两项
- 6-12 条为典型区间；长材料拆成 2-5 页、每页 2-4 条
- 不加评论（不写"路转粉"、"太精彩"、"值得学习"）
- 不用引号和破折号
- 每一条能回到来源锚点

## 常见失败

1. 标题听起来像文章导语
2. 先写漂亮总结再找材料
3. 把访谈问题的驱动感洗掉
4. 按生成者的论证逻辑重排材料顺序
5. 用"本质"、"真正"等词替材料说话
6. 把数字和例子藏在副文里
7. 人为拔高结尾
8. 把核心总结写成读后感
