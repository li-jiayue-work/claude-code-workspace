# 笔记型骨架（L23-L32）

专为播客复盘、长文章、人物稿、深度报道设计。目标不是宣告观点，而是把读者真正会记下的重点、句子、线索和证据排列出来。

## L23 — 界面证据

- 左侧主张 + 三个证据点
- 右侧真实界面截图或占位
- 适用：产品 UI、系统方案、工具链

## L24 — 原文摘录 + 侧注

- 签章：`callout-mark`（6mm 实心小方块取代蓝条）
- 左列：原文摘录（≤36 中文字符，宽度 ≤14em）
- 右列：侧注与语境说明（≤18em）
- 容器：`--w-note`

## L25 — 段落拆解

- 顶部：一句话概括段落重点
- 下方三列：Fact（事实/场景）→ Point（推进理解的重点）→ Aftertaste（留在读者脑中的余味）
- 默认垂直居中，使用 `note-stack`

## L26 — 线索词追踪

- 同一关键词在不同位置的语义变化
- 三列：第一次出现 → 中段变化 → 最后落点
- 适合播客复盘和长文章

## L27 — 观点 + 例证

- 一个重点搭配二到三个具体例子
- 比观点加解释更实在
- 适合长文章和复盘材料

## L28 — 一句原话，多层注解

- 上：短原话（≤28 中文字符），`bare` + `callout-mark`
- 下：三层注解（回应/重点/余味）
- 上窄（`--w-quote`）下宽（`--w-default`）

## L29 — 文章脉络

- 四节点：起点 → 展开 → 转折 → 落点
- 签章：`timeline-row thick`，1.5px 连接线
- 容器：`--w-wide`

## L30 — 双张力

- 两股同时成立、互相拉扯的力量
- 不是 before/after 对比，是同时在场
- 并排展示 Tension A 和 Tension B

## L31 — 未解问题

- 材料停下来的地方：未被回答的问题、后续值得追的线索
- `bare` 去页眉，`--w-quote` 窄宽度
- 列举 3 个开放式问题
- 不做总结，不"上价值"

## L32 — 核心总结

- Deck 结尾的高获得感笔记页
- 编号：`summary-num`（衬线粗体、7vw、accent 色）
- 每页 2-4 条，每条有细节、有获得感
- Chrome 简化：只写"核心总结"和页码
- 默认深色页，不加卡片、边框、引号或装饰图形
- 多条时可连续使用，标记 series=true
