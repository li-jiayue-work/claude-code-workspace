# Workflow: Debug

## 阶段

```
报告 → 复现 → 定位 → 修复 → 回归 → 沉淀
```

## 步骤

### 1. 接收报告 (5%)

- 收集：错误描述、复现步骤、日志、环境信息
- 分类：P0/P1/P2/P3
- 检查是否已知问题（查 memory/mistakes.md）

### 2. 复现 (20%)

- 尝试在本地/测试环境复现
- 确认复现条件
- 如果不能复现，标注为 `[无法复现]`，输出已知信息后等待更多数据

### 3. 定位 (30%)

- 调用 debugger agent
- git log / git bisect 查找引入 bug 的 commit
- 输出根因分析

### 4. 修复 (25%)

- 分支：`fix/<description>`
- 最小修复原则
- 添加回归测试
- 评估修复是否引入新问题

### 5. 回归验证 (15%)

- 确认原始 bug 不复现
- 相关功能的回归测试通过
- 调用 reviewer agent

### 6. 沉淀 (5%)

- 更新 memory/mistakes.md
- 更新 memory/learnings.md
- 如为 P0/P1，触发事后复盘

## 决策门

- 复现失败 → 不进入修复
- 根因不明确 → 不开始写修复代码
- reviewer 未通过 → 不合入

## 禁止事项

- 不复现就写修复
- 不写回归测试
- 不止血就开始根因分析（P0/P1）
- 不更新 memory/mistakes.md
