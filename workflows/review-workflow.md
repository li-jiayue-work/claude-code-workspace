# Workflow: Review

## 触发时机

- PR 提交时
- Feature 开发编码完成后
- Bug fix 完成后
- Refactor 每步完成后

## 阶段

```
提交 → 自动检查 → reviewer agent → 人工确认 → 修复 → 通过 → 合入
```

## 步骤

### 1. 提交准备

- 确认改动范围（git diff 检查）
- 确认没有无关文件变更
- 确认没有调试代码残留

### 2. 自动检查

- reviewer agent 按检查清单逐项检查
- 重点检查 ARCHITECTURE.md 规则
- 标注阻塞性和非阻塞性问题

### 3. Reviewer Report

- 输出标准化审查报告（见 reviewer agent 格式）
- 严重度分级：
  - **阻塞**：必须修复才能合入
  - **建议**：应修复，可在后续 PR 中处理
  - **注意**：值得关注，但不必立即处理

### 4. 修复循环

- 逐一处理审查意见
- 每次修复后重新验证
- 修复完成后再次通过 reviewer agent

### 5. 合入

- 所有阻塞项已修复
- 测试通过
- commit message 合规

## 审查重点权重

1. 安全性 — 最高优先级
2. 正确性 — 边界条件和异常处理
3. 架构合规 — 不破坏模块边界
4. 可维护性 — 命名和结构
5. 性能 — 仅在明显问题时

## 禁止事项

- 不因非阻塞性问题阻塞合入
- 不在审查中加入新需求
- 不跳过安全问题的检查
- 不在修复审查意见时扩大修改范围
